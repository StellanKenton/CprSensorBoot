# OTA 升级通信协议

## 协议概述
本协议定义了APP与MCU之间进行OTA（空中下载）固件升级的通信规范。所有通信帧使用统一格式，通过串口或蓝牙等通信方式进行传输。

## 通信帧基本格式
所有通信帧使用以下统一格式：

| 字段 | 长度 | 描述 | 示例值 |
|------|------|------|--------|
| 帧头 | 2字节 | 固定为 0xFAFC | FA FC |
| 版本号 | 1字节 | 协议版本号 | 01 |
| 命令编码 | 1字节 | 指令功能码 | EA-EB-EC-ED-EE |
| 数据长度 | 2字节 | 数据域长度（小端字节序） | 00 02 |
| 数据域 | 变长 | 指令具体数据 | 可变 |
| 校验码 | 2字节 | CRC16校验码 | CRC16 |

## 1. 获取设备信息 (0xEA)

### 1.1 APP请求设备信息
**功能**：APP向MCU请求设备当前固件版本和支持的最大单包长度。

**数据帧格式**：
```
FA FC 01 EA 00 02 00 C8 [CRC16]
```

**数据域说明**：
- 固定值 0x00C8（200字节），表示APP建议的最大包长度

### 1.2 设备返回设备信息
**功能**：MCU返回设备当前固件版本和实际支持的最大单包长度。

**数据帧格式**：
```
FA FC 01 EA 00 02 Data [CRC16]
```

**Data格式**：

| 字段 | 长度 | 描述 | 备注 |
|------|------|------|------|
| Flag | 1字节 | 标志位 | 保留字段 |
| Version | 4字节 | 当前固件版本号 | 格式：主.次.修订.构建 |
| 蓝牙模组 Len | 2字节 | 蓝牙模块最大单包长度 | 单位：字节 |
| Mcu Len | 2字节 | MCU最大单包长度 | 单位：字节 |

**版本号示例**：
- 0x01 00 02 00 表示版本 V1.0.2.0
- 每个字节对应一个版本号部分：主版本.次版本.修订版本.构建版本

**长度使用规则**：
- 取蓝牙模组长度和MCU长度的较小值
- 实际传输时使用两者中的最小值

## 2. 升级开始请求 (0xEB)

### 2.1 APP发送升级请求
**功能**：APP向MCU发送升级开始请求，包含固件文件信息。

**数据帧格式**：
```
FA FC 01 EB 00 23 Data [CRC16]
```

**Data格式**：

| 字段 | 长度 | 描述 | 备注 |
|------|------|------|------|
| 文件版本 | 4字节 | 升级固件版本号 | 格式同设备版本 |
| 文件长度 | 4字节 | 固件文件总长度 | 单位：字节 |
| CRC32 | 4字节 | 固件文件CRC32校验值 | 对整个文件计算 |

**示例**：
- 文件版本 0x01000200 表示 V1.0.2.0
- 文件长度 0x000186A0 表示 100,000字节

### 2.2 设备返回升级准备状态
**功能**：MCU验证升级请求，返回准备状态。

**数据帧格式**：
```
FA FC 01 EB 00 09 Data [CRC16]
```

**Data格式**：

| 字段 | 长度 | 描述 | 备注 |
|------|------|------|------|
| State | 1字节 | 升级状态 | 见状态码说明 |
| 已储存文件长度 | 4字节 | 已存储的文件长度 | 断点续传时使用 |
| 已储存文件 CRC32 | 4字节 | 已存储文件的CRC32 | 断点续传时使用 |

**State状态码**：

| 状态码 | 值 | 说明 |
|--------|----|------|
| 正常升级 | 0x00 | 可以开始升级 |
| 版本过低 | 0x01 | 文件版本低于或等于当前版本 |
| 文件过大 | 0x02 | 文件大小超过设备存储范围 |

## 3. 文件续传请求 (0xEC)

### 3.1 APP请求续传
**功能**：APP请求从指定位置开始续传文件。

**数据帧格式**：
```
FA FC 01 EC 00 04 Offset [CRC16]
```

**数据域**：
- Offset：4字节，文件起始传输偏移量（字节）

### 3.2 设备返回续传偏移
**功能**：MCU返回实际要求的传输偏移量。

**数据帧格式**：
```
FA FC 01 EC 00 04 Offset [CRC16]
```

**数据域**：
- Offset：4字节，MCU要求的起始传输偏移量（字节）

## 4. 数据传输 (0xED)

### 4.1 APP发送数据包
**功能**：APP发送固件数据包到MCU。

**数据帧格式**：
```
FA FC 01 ED Len Data [CRC16]
```

**Data格式**：

| 字段 | 长度 | 描述 | 备注 |
|------|------|------|------|
| 包号 | 2字节 | 数据包序号 | 从0开始递增 |
| 当前包数据长度 | 2字节 | 当前包实际数据长度 | 单位：字节 |
| 当前包数据 CRC16 | 2字节 | 当前包数据的CRC16 | 对数据部分计算 |
| 当前包数据 | n字节 | 实际传输的数据 | n ≤ 最大单包长度 |

**注意**：
- 最后一包可能小于最大单包长度
- 包号从0开始，依次递增
- 数据长度应包含在最大单包长度限制内

### 4.2 设备返回接收状态
**功能**：MCU返回数据包接收结果。

**数据帧格式**：
```
FA FC 01 ED 00 01 State [CRC16]
```

**数据域**：
- State：1字节，接收状态码

**State状态码**：

| 状态码 | 值 | 说明 |
|--------|----|------|
| 成功 | 0x00 | 数据包接收成功 |
| 包号异常 | 0x01 | 包号不连续或错误 |
| 长度不一致 | 0x02 | 数据长度与声明不符 |
| CRC校验失败 | 0x03 | 数据CRC校验错误 |
| 其他错误 | 0x04 | 其他未定义错误 |

## 5. 升级结束 (0xEE)

### 5.1 APP发送升级结束
**功能**：APP通知MCU固件传输完成。

**数据帧格式**：
```
FA FC 01 EE 00 00 [CRC16]
```

**数据域**：无

### 5.2 设备返回升级结果
**功能**：MCU返回固件验证和升级结果。

**数据帧格式**：
```
FA FC 01 EE 00 01 State [CRC16]
```

**数据域**：
- State：1字节，升级结果状态码

**State状态码**：

| 状态码 | 值 | 说明 |
|--------|----|------|
| 成功 | 0x00 | 固件验证成功，准备重启 |
| 数据总长度错误 | 0x01 | 接收数据总长度与声明不符 |
| 长度不一致 | 0x02 | 数据包统计长度错误 |
| 其他错误 | 0x03 | 固件验证失败等其他错误 |

## 升级流程

### 正常升级流程
1. APP发送0xEA命令获取设备信息
2. 设备返回0xEA响应，包含版本和最大包长度
3. APP发送0xEB命令开始升级，携带固件信息
4. 设备返回0xEB响应，状态码为0x00表示可升级
5. APP循环发送0xED命令传输数据包
6. 设备对每个数据包返回0xED响应，状态码为0x00表示成功
7. APP发送0xEE命令结束升级
8. 设备返回0xEE响应，状态码为0x00表示升级成功

### 断点续传流程
1. APP发送0xEA命令获取设备信息
2. 设备返回0xEA响应
3. APP发送0xEB命令开始升级
4. 设备返回0xEB响应，状态码为0x00，并返回已存储长度和CRC
5. APP发送0xEC命令，指定续传偏移量
6. 设备返回0xEC响应，返回实际续传偏移量
7. 从指定偏移量开始继续传输数据包
8. 后续流程同正常升级

## 错误处理
1. **数据包传输错误**：当设备返回非0x00状态码时，APP应重传当前数据包
2. **连接中断**：连接中断后，APP应从断点处续传
3. **校验失败**：CRC校验失败时应重传对应数据包

## 注意事项
1. 所有多字节数值采用小端字节序
2. CRC16校验范围：从帧头到数据域结束
3. 最大单包长度应包含数据包头部的6字节
4. 实际数据包长度 = 2(帧头) + 1(版本) + 1(命令) + 2(长度) + n(数据) + 2(CRC)
5. 升级过程中应保持连接稳定，避免频繁断连
6. 建议在传输前计算整个文件的CRC32，传输完成后验证
